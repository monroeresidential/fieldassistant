**What each later milestone adds to the codebase (so milestone 1 leaves room for it):**

- Milestone 2: `api/internal/llm`, `api/internal/pipeline` (drafts, lookup cache), `api/internal/features/rfi` (schema, prompt.md, extract), `lookup_cache` and `drafts` and `audit_events` tables, `/projects/{id}/lookups/{kind}`, `/drafts` endpoints; iOS `Core/Capture`, `Core/Review`, `Core/Lookups`, `Features/RFI`.
- Milestone 3: `api/internal/jobs` (River workers), `attachments` table, `/attachments` and `/drafts/{id}/submit` and `/jobs/{id}`; iOS `Core/Drafts` (SwiftData queue, BackgroundTasks).
- Milestone 4: `/projects/{id}/features` permission probing, 422 field-error mapping, Fastlane `beta` lane wired to App Store Connect.

## Follow-ups from Phase 1 verification (2026-10-23)

- Sandbox sign-in verified end to end on the simulator: Procore login, PKCE callback, session, company list. Project list requires the app to be installed in the Procore company (Procore 403 "App is not connected to this company."); document this in `deploy/README.md` for production onboarding.
- Surface Procore's reason on the iOS "No access" screen (pass the Procore error text through `procore_permission_denied` responses) instead of the generic admin-access copy. Fits milestone 4 (permission errors).
- Development and production environments (`develop` → `api-dev.fieldassistant.tools`, `main` → `api.fieldassistant.tools` via PR), GitHub environments and branch protection. Decided: one droplet with two stacks behind one Caddy, deployed per branch (no tag deploys); see `deploy/README.md`.
- Refresh-token reuse grace window (strict revocation vs lost responses on poor signal): Drew to decide before the pilot.
- Live UI smoke test (`FieldAssistantUITests`, gated by `FA_UI_LIVE=1`) exists; extend it past login once a sandbox test account can be injected safely.

## Follow-ups from the dev environment bring-up (2026-10-24)

- Dev stack verified end to end from the iOS Dev build: sandbox sign-in, token exchange, company and project list, RFI list against `api-dev.fieldassistant.tools`.
- Hardening (milestone 4): the app refetches `/companies/{id}/projects` on every selection change (three fetches in ten seconds while switching projects). Cache the project list per company for the session and refresh it only on pull-to-refresh or company change.
- Prod stack is created but stopped until a production Procore app exists; `.env.prod` on the droplet needs only the Procore client id and secret.

## Follow-ups from milestone 2 (2026-10-24)

- Project sync (Drew's direction after the first on-device submit): the phone holds all fields of every RFI on the project, syncs on app open and from a per-project Sync button, and the design treats the whole project as the sync unit so observations and punch items reuse it. Spec `docs/superpowers/specs/2026-10-25-project-sync-design.md`; backend merged and verified on dev 2026-10-25 (PRs #9, #10); the iOS plan `2026-10-25-project-sync-ios.md` is merged (PR #12) and passed the device check on 2026-10-26. Follow-ups from review: a name-only `created_by` for questions in the contract; `apply()` fetches every project row per page and `records()` filters in memory (fetch by page ids, push query and sort into the `FetchDescriptor`, hoist the per-call JSON coders in `CachedRecord`); match "Ball in my court" on the Procore user id (store `ballInCourtID`) instead of the name; move `RouteTransport` to `FieldAssistantTests/Support/` and fail loudly on unrouted paths; re-use an already downloaded attachment on re-tap and hoist the QuickLook sheet off the lazy row; `testApplyIsOneSavePerPage` should disable autosave; a Go test pinning the forwarded attachment `Content-Type` on the wire; "Synced 2 min. ago" short-units punctuation. Still open from verification: whether Procore's list stops returning a recycled RFI (the sandbox kept listing one), second-user visibility, an RFI with attachments. Replaces "link to Procore to see RFIs".
- Backend: parse Procore's `errors` map on HTTP 400 as well as 422 so the field is flagged (Procore answered 400 `rfi_manager_id invalid` for a user without RFI-manager permission); source RFI manager candidates from Procore's `potential_rfi_managers` (milestone 4 permission probing).
